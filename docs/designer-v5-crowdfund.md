# 桌游设计师 v5 扩展计划：曝光 · 预热 · 平台 · 事件

> 状态：设计定稿待评审，未实施。基于 v4 众筹系统（docs 以对话定稿为准）。
> 目标：解决「攒灵感 → 堆迭代 → 干等到期」的单调循环，增加设计期经营决策、预热经营、众筹期随机事件与平台选择。

## 0. 现状痛点

当前流程：游玩得灵感 → 立项 → 6 维度迭代（纯灵感堆叠）→ 发起众筹 → 30~120 天逐秒模拟 → 到期结算 → 垫资交付。
玩家在项目挂上之后几乎零操作，成败在点「发起」时就已注定。

## 1. 总览：新流程

```
游玩得灵感 → 立项 → 迭代打磨 + 经营曝光（试玩/宣传/设计日记）
  → 选择平台（某点5%高曝光 / 某集3%低曝光）→ 预热期（积累看好人数）
  → 众筹期（看好转化初始支持 + 逐秒模拟 + 每5天随机事件抉择）
  → 到期结算（成功：立即到账50%货款−抽成；交付：垫资成本+收回剩余50%−抽成）
```

核心新增资源：**曝光度（exposure）**——项目级数值，贯穿设计期与预热期，决定预热积累的「看好人数」与众筹期的自然流量。

## 2. 曝光度系统（设计期经营）

每个原型独立积累 exposure。三类活动，各有冷却/递增成本，避免单一最优解：

| 活动 | 消耗 | 产出 | 属性挂钩 |
|---|---|---|---|
| 组织试玩 | 金钱（¥50×2ⁿ，n=已办次数） | 曝光 +8~15，看好种子 +0~3 | 沉浸/应变每级 +4% 产出 |
| 社媒宣传 | 金钱（¥30×1.6ⁿ） | 曝光 +5~10 | 无（纯花钱买量，效率递减） |
| 设计日记 | 灵感 3 | 曝光 +4 | 无（灵感第二条出路，缓解 cap 999 溢出） |

限制：试玩与宣传各有每日次数上限（如各 3 次/天游戏时间）；曝光对每个项目设软上限（如 200，超出部分收益减半），防止发售前刷满。

## 3. 预热阶段与时间池

- **时间池（核心决策）**：发起时选定总期限 T ∈ [30, 120] 天（沿用现有范围），并在池内分配——预热 P 天 + 众筹 T−P 天。P ∈ [5, min(30, T−15)]（预热最短 5 天、最长 30 天不可再长；众筹至少留 15 天）。预热不是众筹外的附加阶段，而是总时长的一部分。
- **时机**：迭代满意后，先**选定平台**（不可更换），再设定 T 与 P，进入预热。
- **看好人数（watchers）逐日积累**：

  ```
  每日新增看好 = round((exposure/10 + 平台基础曝光) × 定价亲和 × 质量系数)
  平台基础曝光：某点 25 / 某集 12
  定价亲和：100% 定价 = 1.2，1000% 定价 = 0.6，线性
  质量系数：0.8 + 0.004×Q（Q100 = 1.2）
  ```

- 预热期间仍可继续花金钱追加宣传（只加曝光，按剩余天数折算看好）。
- **众筹开启瞬间**：看好人数 × 转化率转为初始支持者：
  `转化率 = 15% + min(15%, Q/10 × 1%) − 溢价惩罚((定价倍率−1)×2%)`，下限 5%。
- **张力**：预热越长 → 初始支持越多、起跑即抬高每秒基础关注（支持/100 加成），但众筹剩余天数越短（逐秒累积少、事件次数少）；预热短则相反，冷启动风险大。平台差异联动时间分配：某点预热效率高，适合短预热快冲型；某集更依赖长众筹期逐秒稳攒。
- **不做**：预热期不可花钱延长（用户定稿）。

## 4. 众筹期随机事件

- **触发**：众筹期内每 5 天（= 120 秒现实）判定一次，60% 概率生成事件；可多个事件同时待决（见下方窗口规则）。
- **处理窗口**：每个事件生成后独立拥有 **5 天倒计时**（= 120 秒现实）。窗口内玩家可主动抉择；超时未处理则自动执行该事件的**默认选项**（不消耗任何资源的选项，结果通常为中性或负面）。
- **离线规则**：离线期间项目照常推进、事件照常生成；玩家回来后**一次性批量处理**窗口内待决事件（各自倒计时独立）。若回来时已处众筹**最后 5 天**（或离线期间跨过该界线），所有待决事件按默认选项自动结算，不再弹抉择。
- **需求三类**：① 属性等级 ≥ N（六维：谋略/演算/应变/洞察/运筹/沉浸，门槛 8~15，给核心属性养成提供出口）；② 金钱（按当前成交额 supporters×售价 的百分比 1%~6%，保证全周期都有意义）；③ 灵感（3~8）。
- **结果两类**：支持者 ±3%~±10%（按当前人数取整，不扣到 0 以下）；曝光增减（作用于剩余天数的每秒流量，+25%~+50% 乘区）。
- **历史记录**：事件触发/抉择/结果全部记入 campaign.eventHistory（发生天数、所选选项、是否默认兜底、结果数值），项目卡与结算页可回看。
- **默认选项原则**：绝不优于主动投入的上限（通常 0 或负收益），保证「参与决策」始终有意义。

## 5. 平台系统与结算规则（用户定稿）

| 平台 | 抽成 | 预热基础曝光 | 定位 |
|---|---|---|---|
| 某点 | 总成交额 5% | 高（25/日） | 流量大、到手少 |
| 某集 | 总成交额 3% | 低（12/日） | 精准、到手多 |

**结算（到期达标）**：
- 平台抽成 = 支持者 × 售价 × 抽成率（总成交额抽成）。
- **立即到账**：50% ×（货款 − 抽成）——众筹一结束先到一半钱。
- **交付时**：垫资 支持者 × 成本价，同时收回剩余 50% ×（货款 − 抽成）。
- 净收益 = 支持者 × (售价×(1−抽成) − 成本价)，溢价 < 抽成率时可能亏损（现实感）。
- funded 记录扩展：`commission / firstPayment / remainPayment`。
- 失败：无资金往来，原型退回（现状不变）。

## 6. 参考摩点/新物集的附加玩法（建议，可裁剪）

1. **里程碑解锁项**：达到目标 150% / 200% 时自动触发「解锁回报」——支持者小浪潮（+3%/+5%）并记录展示。复用现有「满额继续累积」，奖励化。
2. **看好排行/预约**：预热期看好人数本身作为成就统计（「未发售先火」成就：预热看好 ≥500）。
3. 暂不做：解锁项自定义、多档价位（all-in/早鸟档）、话题区互动。

## 7. 技术改动清单

- **state.ts**：Prototype 加 `exposure / activities(各类已办次数)`；DesignCampaign 重构为状态机 `status: 'preheat'|'live'`，加 `platformId / watchers / exposure / pendingEvent / eventHistory`；FundedDesign 加 `commission / firstPayment / remainPayment`。
- **data/designs.ts** 调参区新增：PLATFORMS（两平台）、ACTIVITIES（三活动）、PREHEAT 参数、EVENT_POOL（事件表）、结算比例常量。
- **engine/design.ts** 新动作：`runActivity`（三种经营）、`startPreheat`（选平台+预热天数）、`resolveEvent`；`tickCrowd` 拆出 `tickPreheat` + 事件判定钩子；到期结算改两阶段+抽成；`deliverDesign` 改剩余 50% 结算。
- **离线**：accumulateOffline 复用 tick（事件照常生成、倒计时照常走；超窗/终局前 5 天的按默认选项结算，回来的待决事件批量弹窗处理）。
- **UI（DesignPage.vue）**：原型卡加经营按钮组；预热面板（平台对比卡、看好曲线、追加宣传）；事件抉择弹窗（选项需求置灰）；结算明细展示抽成与两阶段到账。
- **存档**：SAVE_VERSION 15→16；旧 campaign 归一化（补 platformId 默认某点、watchers 0），旧 funded 归一化（commission 0、firstPayment 0、remainPayment=income，保持旧全额交付行为）。
- **测试**：新增预热换算、平台抽成结算、事件触发/需求/结果、存档迁移用例；目标 220+ 全绿。
